Featured case study · Full-stack ownership

FinTrack — an offline-first personal finance platform, four clients deep

Where I took a shipped Flutter app and rebuilt it as a full-stack, sync-driven product — then proved the architecture translates by shipping the same platform on native iOS, native Android and React Native, all against one NestJS + PostgreSQL backend, deployed and live-verified end to end against real infrastructure.

  • One backend, four independent clients. Flutter (production), native iOS (Swift/SwiftUI), native Android (Kotlin/Jetpack Compose) and React Native (Expo) each implement the same offline-first sync architecture from scratch in their own idiomatic stack — not a shared codebase.
  • Offline-first sync engine. Outbox queue, per-record delta sync, retry with exponential backoff, and explicit version-gated conflict resolution — reimplemented per platform (Hive/GetX, SwiftData, Room/Hilt, MMKV/Zustand).
  • Real backend, real database. NestJS + Prisma against PostgreSQL (Neon), JWT auth with rotating refresh tokens, deployed on Render and verified against production — not mocked in tests.
  • Dual-write architecture. One Google sign-in writes to Postgres (primary) and Google Drive (permanent backup); the sync engine's remote target is pluggable, so this needed no change to the outbox/worker.
  • Push notifications that matter. Budget-exceeded, low-balance and monthly-income alerts via FCM, verified on a real device against real backend data.
  • Encryption at rest. AES-256 / MMKV encryption / SwiftData secure storage depending on platform, Keystore/Keychain-backed credentials, migration tested against real pre-existing device data.
  • Full English / Bangla localization. Every screen on every client, with zero-restart language switching.
  • CI/CD + hardening. GitHub Actions runs analyze / test / lint plus an e2e suite on an ephemeral Postgres; rate limiting, security headers and Dependabot live in production.
